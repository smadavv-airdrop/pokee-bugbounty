PoC: Enterprise Tenant Subdomain Enumeration

Target: pokee.ai Enterprise API (your-tenant.enterprise.pokee.ai)

Severity: MEDIUM (CVSS 5.3)

Vulnerability Description

Enterprise tenants on pokee.ai receive dedicated subdomains under the pattern your-tenant.enterprise.pokee.ai. There is no protection against subdomain enumeration, allowing attackers to discover valid tenant subdomains and target them specifically for further attacks (credential stuffing, authentication bypass, API abuse).

Evidence

Documentation Reference: https://docs.pokee.ai/docs/api-reference
Endpoint Format: https://your-tenant.enterprise.pokee.ai
Authentication: pk__ format

The documentation explicitly shows the subdomain pattern, confirming the naming convention for enterprise tenants.

Proof of Concept

This PoC demonstrates subdomain enumeration by attempting to resolve common tenant subdomain names.

Manual Verification Commands

# Check if enterprise.pokee.ai exists dig enterprise.pokee.ai # Check for wildcard DNS dig random-nonexistent.enterprise.pokee.ai # Try common tenant names for tenant in demo test staging dev prod api admin internal; do dig +short $tenant.enterprise.pokee.ai done

Impact

  • Tenant enumeration enables targeted attacks against specific enterprise customers
  • Attackers can identify valid tenants, then attempt authentication bypass
  • Credential stuffing against known tenant subdomains
  • API abuse against known tenants
  • Information disclosure about customer base

Remediation

  • Implement subdomain enumeration protection (wildcard DNS with authentication at edge)
  • Use non-guessable tenant identifiers (UUIDs instead of names)
  • Require VPN/private network access for enterprise API
  • Implement rate limiting on subdomain resolution attempts
  • Monitor and alert on enumeration attempts
